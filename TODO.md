# To do

The repository's to-do list: engineering items that need no external answer, and the decisions
only the Operator can take. Kept by the **secretary**, a back (PROCESS.md): after each turn it
adds the items and decisions a session left open and ticks the finished ones; it never rewords,
removes or reorders, and a guard undoes a run that does. Hosts reword, merge, split, move or
remove items by hand, normally at a ledger review.

An item reads `- [ ] **ID Title** (owner). What and why. Added YYYY-MM-DD.`; the owner is host
(a session can do it), the Operator, or engineers; a ticked item ends `Done YYYY-MM-DD.` and
stays. Ids are short descriptive slugs (two to four kebab-case words naming the item), unique in the file, never reused, never renamed.

- [ ] **fleet-reconcile-live-sessions The fleet launcher reconciles live sessions after a rebuild** (host). Requested by a consuming repository (AOF, 2026-10-24) after two days of running four agents in one devcontainer with a stopgap launcher; it follows the HOST_SESSION-after-/clear request. Five lessons for `devcontainer:claude:fleet`: (1) `claude agents --json` also lists ended sessions with no pid, so count only entries with a live process; (2) the daemon restores background sessions from the claude-code Feature's volume after a rebuild, and a launcher that starts right away races it and makes duplicates, so wait for the restore, then reconcile; (3) killing a session's process does not stop it (the daemon restarts it within seconds): use `claude stop <id>`, never `claude rm <id>`, which can delete the session's worktree; (4) `HOST_SESSION` in a session's environment goes stale after a /clear or a fork, so read the ids from `.devcontainer/.env` first; (5) report duplicates instead of only skipping a start: a fork, a resume from the history list or a hand-started session never passes the launcher, so `--plan` lists every agent with more than one live session (each id, its age, whether it has a transcript) and offers `claude stop` for the extras. Done when: after a rebuild the launcher leaves exactly one live session per agent; a session with no pid never counts as running; a duplicate is reported, stopped with `claude stop` and stays stopped; the ids come from `.env`. Once released, the consumer retires its own launcher and keeps only its agent list. Added 2026-10-24.
