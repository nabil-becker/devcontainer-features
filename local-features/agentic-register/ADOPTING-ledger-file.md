# Adopting the agentic register from a ledger file

The steps for a repository that keeps a ledger in a file (one Markdown file a month, a run log)
and moves onto `agentic-register`. Written for this repository first: its butler carries them out
(backlog item `ledger-move`). Any repository adopting AOF follows the same steps.

Why move: every branch appends to the end of one file, so parallel branches conflict on it. Here
each entry is its own file, named by its hash, so two branches never touch the same file.

```
before                          after
docs/ledger/2026-10.md   -->    frozen as it is; also imported, marked as backfill
docs/ledger/staff-runs.jsonl -> frozen as it is; also imported as run entries
                                docs/ledger/entries/<id>.entry   one file per entry, only added
                                .aof/ledger-anchors              the operators' public keys
                                LEDGER.md                        generated by `show`, never committed
```

## 1. Install the Feature in the manor

Until `features-publish` lands, the Feature is installed from this repository's source: copy
`aof/tooling/src/agentic-register/` into `.devcontainer/` at build and reference it as a local
Feature (`"./agentic-register": {...}`; a local Feature must sit under `.devcontainer/`). Once it
is published, reference it by id.

Install it as a Feature, never by running `install.sh` by hand or from a post-create step. Only
the Feature lifecycle creates the named volume behind `$AGENTIC_REGISTER_HOME`. Without the
volume, the agents' keys are made inside the image and are lost at the next rebuild.
`agentic-register-setup` says where the home lives: `(volume, writable)` is right, and
`(image, ...)` means the keys will not survive a rebuild.

Set the options:

```jsonc
"agentic-register": { "registers": "ledger:ledger:docs/ledger/entries", "anchors": ".aof/ledger-anchors" }
```

## 2. The operators' keys never enter the manor

Every agent in the manor runs as the same user, so any of them can read the Feature's volume. An
operator's private key therefore stays on the operator's own machine:

```
# on the host, once per operator, with a passphrase:
ssh-keygen -t ed25519 -C "" -f ~/.ssh/aof-ledger
ssh-add -c ~/.ssh/aof-ledger          # -c: the host asks before every signature
```

The editor forwards the SSH agent into the container. Inside it, the operator signs with only the
public key (`--key ~/.ssh/aof-ledger.pub`, copied in), and the agent signs on the host. `ssh-add
-c` makes the host ask each time, so an agent cannot sign as the operator while the agent socket
is forwarded.

**On Windows**, the OpenSSH agent refuses keys added with `-c` ("agent refused operation"), so
there is no prompt to rely on. Load the key only for the signing, and remove it straight after.
While the key is out of the agent, nothing in the manor can sign as the operator:

```
# on the host (PowerShell), just before signing:
ssh-add $HOME\.ssh\aof-ledger
# in the manor: the roster, rule or rekey commands, with --key ~/.ssh/aof-ledger.pub
# on the host, as soon as they are done:
ssh-add -d $HOME\.ssh\aof-ledger
ssh-add -l          # "The agent has no identities." or no aof-ledger line
```

Never leave the operator key loaded in a Windows agent between signings.

The anchors file holds the public half, one line per operator, committed:

```
# .aof/ledger-anchors: the operators' keys every reader trusts. Changed only by a reviewed pull
# request with an operator's ruling (the guard in step 6).
operator <ssh-ed25519 AAAA...>
```

## 3. The agents' keys

One key per agent identity per manor, kept in the Feature's volume (`agentic-register key new
<principal>`): `butler`, `framework`, `tooling`, `seed`, `scribe`, `secretary`, `tester`. An
operator adds each one to the roster:

```
agentic-register roster --as operator --key ~/.ssh/aof-ledger.pub \
  --add-key '<the line key new printed>' --principal scribe --role agent
```

Each agent's session sets `AGENTIC_REGISTER_AS=<principal>`, so its entries are signed as itself.
The four main agents' start tasks (`task butler`, ...) are the place to set it.

## 4. Backfill, then freeze

```
agentic-register import --as butler --markdown docs/ledger/2026-10.md --dry-run
agentic-register import --as butler --markdown docs/ledger/2026-10.md
agentic-register import --as butler --runs docs/ledger/staff-runs.jsonl
agentic-register verify
```

Each imported entry carries `backfill: {source, line, date, sha256}`: the file it came from, its
line, its original date, and the hash of its original text. Anyone can check an entry against the
frozen file. Corrections (`Corrects:`, naming the entry by its title or by `<date> <title>`) are
linked to the entry they correct by id; one whose name matches no entry keeps the name in
`backfill.corrects_title`. The signature is the importer's: it says "this import is faithful", not "I did this work". Importing again adds
only what is new. The old files stay where they are, under the existing append-only guard, and
nothing more is appended to them.

## 5. The staff write through the ledger

- The scribe writes each entry with `agentic-register add --as scribe --file <entry.json>` (a
  `work` entry, SPEC.md), not by appending to Markdown.
- Each model run is a `run` entry (`--kind run`), with its cost in `usd_micro`, instead of a
  line in `staff-runs.jsonl`.
- `agentic-register query` gives the ledger review and the dashboard their numbers, for example
  `SELECT who, sum(usd_micro) FROM costs GROUP BY who`.

## 6. The guards

In `task verify`:

- files under `docs/ledger/entries/` are only ever added, never changed or deleted;
- `agentic-register verify` passes: no refused entry, no held entry, no fork;
- `.aof/ledger-anchors` changes only with an operator's ruling recorded in the commit.

And `LEDGER.md` (from `agentic-register show`) is generated, not committed. A committed view would
bring back the conflicts this move removes.

## 7. Check

```
agentic-register check        # every part ready
agentic-register verify       # every entry valid
agentic-register show | head  # the backfill first, then what came after
```
