# Adopting the agentic register

How a repository moves its shared records onto `agentic-register`: the ledger and the backlog
first, then any other register. Written for this repository first (its butler carries it out:
`manor-switch-agentic-register`, then the backlog's move), and for any repository adopting AOF.

Why: a record that every branch edits in one file (a monthly ledger, a `TODO.md`) conflicts as
soon as agents work in parallel. In a register each change is its own file, named by its hash, so
two branches never touch the same file, and the changes that really disagree are flagged for a
person instead of failing a merge.

```
before                              after
docs/ledger/entries/ (agentic-ledger)  -->  the register `ledger`, unchanged: format-1 entries stay valid
TODO.md, edited by hand              -->  frozen; backfilled into the register `backlog`
                                          docs/backlog/entries/<id>.entry   one file per change, only added
.aof/ledger-anchors                  -->  the anchors of every register (the same file, or renamed)
LEDGER.md, a generated TODO view     -->  generated by `show`, never committed
```

A repository that starts from a ledger file instead (a monthly Markdown file, a run log) first
follows [`ADOPTING-ledger-file.md`](ADOPTING-ledger-file.md) first. `import --markdown` and `import --runs` work the same.

## 1. Switch the manor from agentic-ledger to agentic-register

The Feature is installed from this repository's source until `features-publish` lands, as
`agentic-ledger` is today (`task initialize` copies it into `.devcontainer/`):

```jsonc
"./agentic-register": {
  "registers": "ledger:ledger:docs/ledger/entries; backlog:backlog:docs/backlog/entries",
  "anchors": ".aof/ledger-anchors"
}
```

**The keys move with it.** Each Feature keeps its keys in its own volume, and a new Feature id
is a new volume. For one rebuild, install both Features, so both volumes are mounted, and copy the
agents' keys and the record of checked signatures across:

```
cp -a /var/lib/devcontainer-features/agentic-ledger/keys/. "$AGENTIC_REGISTER_HOME/keys/"
cp -a /var/lib/devcontainer-features/agentic-ledger/checked "$AGENTIC_REGISTER_HOME/checked"
agentic-register check --as butler          # every part ready
agentic-register verify --register ledger   # the same entries as agentic-ledger verify
```

Then remove `./agentic-ledger` from `devcontainer.json`. Nothing else in the ledger changes:
its store, its roster and its anchors are the same, and `agentic-register` reads its format-1
entries as the register `ledger`'s. New entries are format 2.

Every place this repository names the old Feature moves to the new one (from `git grep
agentic-ledger`, outside the Feature itself):

| Where | What changes |
|---|---|
| `.devcontainer/devcontainer.json`, `Taskfile.yml` (`initialize`) | the Feature copied and installed |
| `Taskfile.yml`, the four start tasks | `AGENTIC_LEDGER_AS` becomes `AGENTIC_REGISTER_AS` |
| `scripts/staff/staff.py`, `test_staff.py` | the command (`agentic-register`, `--register ledger`), the source path in the tests |
| `scripts/verify.sh`, `test-verify.sh`, `test-worktree.sh` | the command and `AGENTIC_REGISTER_HOME`; `verify` for each register |
| `.gitignore` | `.devcontainer/agentic-register/`, and each store's `.lock-*` files |
| `.claude/skills/ledger-review/SKILL.md` | `agentic-register query`, `show` and `add` (the ledger is the default register) |
| `PROCESS.md`, `LEXICON.md`, `docs/architecture/`, ADR 0006 | the words, the drawings and the record |

The frozen `docs/ledger/2026-10.md` and its history keep the old name: they are records.

## 2. Each register has its own roster

Being allowed to write the ledger says nothing about the backlog. An operator adds each key that
writes the backlog to its roster, once, signing through the SSH agent as before (the private key
never enters the manor; `ssh-add -c` makes the host ask each time; on Windows, which refuses `-c`,
load the key with `ssh-add` just before and remove it with `ssh-add -d` straight after:
`ADOPTING-ledger-file.md`, step 2):

```
for p in butler framework tooling seed secretary; do
  agentic-register roster --register backlog --as operator --key ~/.ssh/aof-ledger.pub \
    --add-key "$(agentic-register key show "$p" --json | jq -r .key)" --principal "$p" --role agent
done
```

Until that is done, nobody can write the backlog, and `add` says so (`unknown-key`).

Keys get lost: a volume is reset, a machine is replaced. Before relying on the registers, see
README.md, "Keys: losing one":

- add a **second anchor** (a second operator, or a second key of yours kept offline), so that
  losing one key never closes the rosters;
- back up the operator key on the host. Agent keys need no backup: `rekey` replaces them;
- **never delete an anchor line**. Retire it with `until=<entry id>` if its key is stolen.

### Rotate an operator key

Do it when the key is lost (the host died, the passphrase is gone), when it may be stolen, or on
a schedule. The procedure is the same, apart from step 3.

1. **Make the new key on the host**, with a passphrase, and keep a copy offline:
   `ssh-keygen -t ed25519 -C "" -f ~/.ssh/aof-ledger-2`.
2. **Add its line to the anchors file, beside the old one, under the same principal.** A line
   is per key, so one principal may have two:
   ```
   operator ssh-ed25519 AAAA...old
   operator ssh-ed25519 AAAA...new
   ```
   Keep the old line's principal as it is. The old key's entries were signed as that principal,
   and moving its line to another principal refuses all of them (`wrong-principal`). Deleting the
   line refuses them too (`unknown-key`, then `refused-parent` for everything after them).
3. **Lost key:** leave the old line as it is. It signs nothing more, but it still checks every
   signature it made. **Stolen key:** end the old line with `until=<entry id>`, the last entry
   the old key signed that you trust. Everything up to that point stays valid, and anything the
   old key signs after it is refused (`retired-anchor`). To find the checkpoint:
   ```
   agentic-register query --register ledger \
     "SELECT id, at, kind FROM entries WHERE key = '<old public key>' ORDER BY n DESC LIMIT 5"
   ```
   Do it for every register: the anchors file is shared, but each register has its own history.
   For a stolen key, also remove it from each register's roster with the new key:
   `agentic-register roster --register <name> --as operator --key ~/.ssh/aof-ledger-2.pub
   --remove-key '<old public key>'`.
4. **Commit the anchors file** in a pull request with your ruling recorded (the guard in step 6
   refuses it otherwise), and from then on sign with the new key: `--key ~/.ssh/aof-ledger-2.pub`.
5. **Check:** `agentic-register verify --register <name>` for every register. Nothing should be
   refused.

This procedure is tested on a throwaway store in `aof/tooling/test/agentic-register/
test_rotation.py`, along with the two mistakes it warns against.

## 3. Backfill the backlog, then freeze TODO.md

```
agentic-register import --register backlog --as butler --todo TODO.md --dry-run   # an add per item, a tick per item done
agentic-register import --register backlog --as butler --todo TODO.md
agentic-register verify --register backlog
# the same items, in the same order:
diff <(agentic-register query --register backlog "SELECT item FROM backlog ORDER BY n" | jq -r '.[].item') \
     <(grep -o '\[[ x]\] \*\*`[^`]*`' TODO.md | sed 's/.*`\(.*\)`/\1/')
```

`show` renders the backlog in the shape of a `TODO.md`, but not byte for byte: the file's own
introduction is not an item and is not imported. Compare the items, as above, not the text.
Rehearsed on this repository's `TODO.md` in a scratch home: 89 changes imported (an add per
item, a tick per item done), `verify` clean, the same items in the same order.

Each item becomes an `add` (and a `tick` when done), marked `backfill` with its line and the hash
of its original text, so it can be checked against the frozen file. Importing again adds only
items that are new or changed. After the import, `TODO.md` is no longer edited by hand. The
guard that froze the old ledger file freezes it too.

## 4. Writers and readers

Writers make changes, never edits of a file:

| Change | Command |
|---|---|
| a new item | `add --register backlog --kind add --data '{"item": "x", "title": "...", "owner": "tooling", "section": "Inbox"}'` |
| done | `add --register backlog --kind tick --data '{"item": "x"}'` |
| reworded, reassigned, moved to another section | `--kind edit --data '{"item": "x", "fields": {"owner": "butler"}}'` |
| prioritised | `--kind move --data '{"item": "x", "after": "y"}'` (`null` for the top) |
| a remark | `--kind note --data '{"item": "x", "text": "..."}'` |

The secretary writes this way. Refinement writes `move` and `edit` entries.

Readers read what the changes add up to:

```
agentic-register show --register backlog                 # the backlog as a TODO.md
agentic-register query --register backlog "SELECT item, owner, title FROM open_items WHERE owner = 'tooling'"
```

"Pull the top open item you own" is the first row of that query. Agents that read `TODO.md` read
this instead. A generated `TODO.md` MAY be kept for people, but never committed: committing it
would bring back the conflicts this move removes.

## 5. Conflicts go to a person

Concurrent changes never block a merge. When two disagree (two edits of one field to different
values, a tick beside a reopen, two moves of one item, an item added twice), both entries are
flagged and `show` lists them under "Needs a person". A person settles one by writing the change
that decides it. `verify` passes with flags: a flag is a question, not a broken record. Refused or
held entries and forks fail it.

## 6. The guards

In `task verify`, for every register:

- files under each store are only ever added, never changed or deleted;
- `agentic-register verify --register <name>` passes;
- the anchors file changes only with an operator's ruling recorded in the commit;
- no generated view (`LEDGER.md`, a generated `TODO.md`) is committed.

## 7. Check

```
agentic-register registers              # ledger and backlog, with their counts
agentic-register check --as butler      # every part ready
agentic-register show --register backlog | head
```
